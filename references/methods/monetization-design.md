# Monetization Design

> Internal method reference for `xhs-monetization-skill`. This file is not an independent Skill.

**Use when:** 有流量但不赚钱，或要设计服务/广告/电商路径

**Scope:** 服务、广告、电商等变现路径与单位经济

**Method intent:** 把小红书流量设计成可测量的商业闭环，比较私域服务、广告合作、电商/店铺等变现方式，并用需求供给、客单价、毛利和转化效率评估路径。

## Use when
- 有流量/粉丝但赚不到钱。
- 要选私域、广告还是电商。
- 要评估某个赛道是否“离钱近”。
- 要算矩阵号、获客或生意规模。

## Five-step monetization path
推荐五步：

1. 战略定位：为什么做、目标变现多少
2. 交易路径：卖什么、通过什么方式收钱
3. 账号定位：昵称、简介、头像等匹配商业目的
4. 打造有效笔记：选题、标题、封面、正文、评论
5. 引流/承接并完成交易

## Mode selection

### A. 私域/服务型变现
适合：高客单、需要咨询、决策复杂、需要个性化沟通的产品或服务。

重点指标：

- 有效私信/咨询量
- 从咨询到可交易联系的转化
- 成交率
- 转化周期
- 客单价
- 毛利率
- 客服时间成本

“更多咨询”不一定更好，应该从泛咨询逐步筛到精准咨询，避免大量低价值沟通吞噬客服能力。

### B. 广告变现
适合：人设/内容本身具备影响力，且品牌愿意为目标受众和内容表达付费。

重点：

- 垂直定位
- 真实分享
- 账号与品牌受众匹配
- 合作案例
- 用户体验不被广告破坏
- 使用当前平台官方合作/报备机制

### C. 电商/店铺/带货
适合：商品可以被内容种草、演示、测评或直播推动决策。

重点：

- 内容是主要流量来源还是商城流量来源
- 商品毛利与履约
- 内容点击到商品页转化
- 退货、复购和售后
- 当前店铺和分销规则

## Demand-supply evaluation
可以用“需供比”判断机会：

- 需求多、供给少：机会大，但红利可能迅速消失
- 需求多、供给多：充分竞争，需要差异和效率
- 需求少、供给少：可能是小而稳的细分市场，但天花板有限
- 需求少、供给多：谨慎进入

判断必须结合真实搜索、评论、成交迹象和自身交付能力。

## Unit economics
把生意拆成可计算链路。例如：

**生意规模 = 流量规模 × 客单价 × 转化率**。

更完整时还要扣除获客、内容、投放、客服、履约和退款成本。

## Matrix scaling
矩阵号用于规模、测试概率和快速放大，但同时带来团队成本、内容成本、账号管理成本和合规风险。

只有当单账号模型已经被验证时才考虑放大。不要用矩阵掩盖定位、产品或转化本身的问题。

## Output format
1. 推荐变现模式
2. 用户从看到内容到付费的路径
3. 每个环节的关键指标
4. 单位经济账
5. 需求/供给判断
6. 放大条件
7. 当前平台规则待核验项
