# Operations Diagnostics

> Internal method reference for `xhs-monetization-skill`. This file is not an independent Skill.

**Use when:** 要诊断账号、做日控/周复盘或找漏斗卡点

**Scope:** 账号诊断、日控、复盘与实验设计

**Method intent:** 用目的、需求、内容漏斗、搜索、互动、咨询和成交数据诊断小红书账号，生成日控、周复盘、异常排查和下一轮实验计划。

## Use when
- “帮我看看这个账号为什么不行。”
- 笔记突然掉流量。
- 做了很多内容但没有咨询。
- 要做日报、周报、复盘或测试计划。

## Diagnostic order
不要从“是不是被限流”开始猜。按更高概率、更可控的顺序检查：

1. 目的是否明确
2. 定位是否匹配业务
3. 需求/选题是否值得写
4. 标题/封面点击效率
5. 正文价值和互动
6. 搜索相关性
7. 主页转粉/信任
8. 咨询承接
9. 成交与交付
10. 最后再检查当前平台合规/账号状态

## Common mistakes
常见误区包括：

- 把商业账号当朋友圈随便发
- 每篇笔记没有明确目的
- 只靠勤奋堆数量
- 只看赞藏，不看交易结果
- 定位不垂直
- 盲目原创而不研究成熟需求
- 只模仿表面，不提炼爆款原因
- 数据不好就频繁删除/修改
- 刷赞藏等异常互动

将这些作为检查项，不作为绝对规则；平台机制变化时要结合当前数据判断。

## Note self-check
发布前检查：

- 目的是什么？
- 选题是否承接真实需求？
- 标题是否有关键词和打开理由？
- 封面是否清楚、统一、有质感？
- 开头是否承接预期？
- 中间是否有实用/情绪/决策价值？
- 结尾是否服务于目的？
- 评论区准备回答什么问题？
- 是否存在虚假、侵权、广告或平台规则风险？

## Daily control
每篇笔记至少记录：

- 发布日期/账号
- 选题与核心关键词
- 曝光/阅读
- 点击或可近似观察指标
- 点赞、收藏、评论、转发、关注
- 主页访问
- 有效咨询
- 成交/订单（若可追踪）
- 内容类型
- 异常备注

矩阵号应按账号与笔记双层看数据，不要只看总量。

## Funnel diagnosis
按“被看见→被点击→被互动→被咨询→成交”定位瓶颈。

每次复盘只选 1-3 个主要卡点，不要一次改十项。

## Experiment design
每轮测试：

- 明确假设
- 只改变少量关键因素
- 设观察窗口
- 记录基线
- 用同类选题/同类账号比较
- 结果好则复制，结果差则回到需求或表达原因

## Output format
1. 诊断结论
2. 漏斗卡点
3. 证据
4. 最高优先级修复项
5. 下一轮 3 个实验
6. 数据监控表字段
7. 需要核验的平台规则/账号状态
